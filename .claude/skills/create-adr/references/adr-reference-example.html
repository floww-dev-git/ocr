§1Context & Problem

Applicants sign approval letters by hand today; officers chase paper. Stories S1–S5 move signing to the DMS digital-sign provider. This record fixes how requests are dispatched, throttled, and costed.

§3Modules & Ownership

plugins/dms owns the request lifecycle; the provider adapter lives in plugins/adapters. No new app.

▸ D1
ChosenDMS owns dispatch
Overa new signing app
BecauseF3 dedup already lives on the DMS document → no new app edge
Only deviations and ownership earn ink here. "DMS owns its own documents" would be an obvious convention — so it's not restated. The card carries the one real choice.
§4Entities & Data Design

SignRequest is born PENDING on officer action, moves QUEUED → SENT → SIGNED | FAILED via callback. A unique (document_id) column enforces F3. provider_ref is read-with-the-row metadata; status is a queried, indexed column.

▸ D2
Chosenstatus as an indexed column
Overstatus inside JSON metadata
BecauseF1 month-end polling filters on status — a queried field must be a column
A lifecycle narrative (born → transitions → ends), never a column dump. The queried-vs-metadata split is decided here, at design time — before a list interactor accidentally filters on JSON.

The interactor door is named and committed here — the step narrative reads like a story at interactor altitude. This section is not deferred to /task-breakdown; a skipped §5 fails the pre-save gate.

The ledger is the fix for the recurring gap: performance, concurrency, rate limits, and cost can't be silently dropped. Each is one line — N/A + reason or → a decision. The cost line carries a real monthly figure with cited volume, so finance gets a number, not a shrug.
§7Failure Handling

429 → backoff + requeue (max 5). Provider timeout → SignRequest FAILED, officer re-triggers. Callback for unknown ref → dropped, logged in the adapter. No partial state: PENDING rows are safe to replay.

§8Extension Cost

Confirmed axis — new provider (FlowwSign): one adapter class + one registry entry, zero core edits.
NOT built: multi-signer routing — no story demands it (YAGNI).

Extension points only on a confirmed axis, with the next-addition cost stated. The flexibility deliberately refused is named too — so a future reader knows it was a choice, not an oversight.
