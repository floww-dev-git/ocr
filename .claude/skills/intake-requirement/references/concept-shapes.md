# Concept Shapes — Step 5/6 Reference

Loaded only at ideation (class 1). The manager is a conceiver here, not a stenographer:
options are GENERATED, grounded in what the confirmed modules can already do.

## Shape format (thin — WHAT-level only)

```markdown
### Shape <A/B/C> — <name>
**JTBD:** <one line — the job the user hires this for>
**Modules touched:** [real dirs from the validated candidate list]
**Trade-off:** <one line — what this shape buys vs costs relative to the others>
```

- 2–3 shapes. One is fine when the ask is genuinely single-shaped — say so rather than
  padding a fake alternative.
- The altitude bar: a user must be able to choose between shapes on BUSINESS grounds. The
  moment a shape needs entity diagrams or port directions to compare, it has crossed into
  the architect's seat — pull it back up or defer that detail to the audit.
- Present via `AskUserQuestion` (recommended shape first). Blending is a valid answer.

## Ideation ≠ invention
Concepts are LABELED PROPOSALS surfaced at the gate for the human to choose. The NO-INVENTION
rule bans smuggling unlabeled requirements PAST the gate; ideation is its sanctioned mirror.
Every shape must trace to the ask + the grounding — never to what would make a nicer system.

## Lock & draft (Step 6)
- Announce: "Locking concept <X> — drafting the PRD." Checkpoint, not a gate — the pick IS
  the approval. Reopens only via evidence (T-triggers, audit findings), never taste.
- The pick is expressed IMMEDIATELY as the PRD's sections (same sitting, one continuous move):
  **Chosen Concept** (the shape, 2–3 lines) · **Rejected Shapes** (each with its one-line
  why-not — six weeks later "why not the rule-builder?" must not be archaeology) ·
  **Assumptions** (what the shape presumes true — each becomes a check the audit verifies).
- Constraints & modules: marked `UNCONFIRMED` in the draft. Only the audit witnesses them —
  a draft PRD never carries confident constraints.
- **The lock test:** a reader with no access to the conversation can answer "what are we
  building, and why this shape instead of the others?" from the PRD alone.

## The conceiver duty (proactive half — outside this skill)
The manager also periodically brings 1–3 unprompted feature/concept ideas (one line + modules
touched each) from scanning the module map, domain docs, and recurring user pain. An idea
enters intake only when the user picks it up — the duty never self-initiates a pipeline.
