The SDLC Process

Artifacts, agents, and skills — each with one job, bound to the engineering canon, and enforced mechanically wherever a machine can hold the line. This is a hub: read the map first — one picture of the whole pipeline, its forking lanes and running threads — then zoom into any phase for its detail. The governing principles live in .claude/rules/references/engineering-canon.md; everything below is their consequence.

1 The pipeline map — one trunk, four lanes, three threads

The million-words picture. Four phases run left to right (the trunk); ◆ gates are the only places the pipeline waits for a human. The trunk is the default class-1 extension path — but triage forks four classes onto their own exit ramps: the update majority lane skips concept planning and rejoins the rail at the impact map (delta-stories only), a bug arcs straight to Build, a module-scale / refactor change loops per slice through Design. Beneath the trunk, three threads run continuously across phases. Click a phase block to zoom: A opens the requirement-phase detail; B / C / D jump to their detail below.

⑂ at triage, four classes pick their exit ramps — see the Phase A zoom · ¹ = class-1-only micro-steps (the update lane skips them: no concept planning, delta-stories only) · * blueprint is optional in Phase B for small, well-understood extensions · security review in C is auto-triggered by sensitive paths

Four gates, everything else auto-chains. Between gates, sub-decisions are announce-and-execute — the pipeline never serially round-trips a human for choices an approved plan already implies. The map is the hub; the stations below and the phase zooms (A · requirement · B · design · C · build & verify) are the spokes.

5 The enforcement ladder — where principles actually live

Proven three times in one day: every fix that stuck moved a principle DOWN this ladder. The ladder is the answer to "how do I test that the agents follow the process."

Rung 1 — Hooksdeterministic

Fire on tool events; cannot be rationalized past. The bottom of the ladder is the top of reliability.

  • quality-gate.sh — cross-app imports (CA dependency rule) · bare except · logging in interactors · property-vs-method no-op · configio row-scope writes
  • check-task-ordering.py — C1–C6: no storage parent before consuming interactors · no storage sub-task before the slice's interactor · no impl before interface · door-before-engines · level-N ordering · slice-naming
  • check-tick-evidence.py — a task tick requires its ✔ artifact · check-dead-contracts.py — every interface/port method requires an interactor call site
  • ruff-check.sh · preflight-check.sh · validate-config.sh
Rung 2 — Skill hard-checksauthoring-time

Run at the moment the artifact is written: Name Replacement Test (ADR) · Hard Checks section (plan) · Step-0 parity inventory (design-module) · memory-driven self-review sweep · branch validation (promote).

Rung 3 — Persona prosejudgment

Reviewer items 10/11 · the architect's extension-cost KPI · rules' WHY sections · agent memory. Prose is where a principle waits for promotion, not where it lives permanently.
